# coupled-tags-lint

`devbox run -- task check` runs ruff and the tests, then builds the flake and lints this repository's tags with the command it packages; run it before finishing. After changing a COUPLED group here, record it with `devbox run -- uv run coupled-tags-lint --update -x README.md -x tests`. `devbox run -- task lint-file -- <files>` formats and fixes the Python files given.

The lint is a functional core (`core/`) with an orchestrator (`orchestrators/lint.py`) and adapters; test the core with plain values, and the command through `tests/test_cli.py`, which runs it as a program. The tag format is defined in coupled-tags (`~/projects/claude/coupled-tags`): its SKILL.md and README, this repository's `core/tags.py` and `core/comments.py`, and its gate hook, which imports them, change together. The lint doesn't read other repositories: a `//<git-host>/<owner>/<name>/<path>` file is checked only for its form and consistency, and listed as not checked. coupled-tags-cross-repo (`~/projects/cli/coupled-tags-cross-repo`) checks across repositories by importing `core/`: what it imports, such as `Tag.repos()`, `Tag.files()` and `compare` with its lock file and update instruction, is its API, as are the `GrepSearch` and `LocalFiles` adapters it wires, so changing them is a breaking change for it. `flake.nix` packages the command for other projects' devbox, which pin a release tag, so a change reaches them only once it's released and they move to the new tag. The flake builds only files git tracks, so a new file needs `git add` before `task tags` sees it.
